# RAG Practice Lab

## 실행 방법

```cmd
docker build -t llama-dev .
docker run --rm -v "%cd%\logs:/logs" llama-dev
```

- 디버그 로그 파일은 `/logs/debug.log` 에 생성됩니다.
- 현재 질의응답 단계는 `MockLLM`을 사용합니다.

# 포맷별 호환성 보고서

## 1. 파싱 품질 테스트

| 파일 | 확장자 | 로드 성공 | 파싱 품질 (상/중/하) | 판단 근거 |
|------|--------|:--------:|:------------------:|----------|
| Text.txt | `.txt` | O | 상 | 본문 텍스트가 자연스럽게 추출되었고 핵심 내용 누락이 거의 없음 |
| Policy.pdf | `.pdf` | O | 상 | 페이지별 텍스트가 안정적으로 추출되었고 한글도 정상적으로 유지됨 |
| SRS.docx | `.docx` | O | 중 | 로드는 성공했으나 실제 본문 구조 보존 여부는 추가 확인이 필요함 |
| CRA.xlsx | `.xlsx` | O | 중 | 표 내용은 추출되지만 `Unnamed:` 컬럼명이 다수 포함되어 표 구조가 평탄화됨 |
| DESIGN.hwp | `.hwp` | O | 하 | 일부 한글 본문은 보이지만 앞부분에 바이너리성 깨짐 문자가 섞여 추출 품질이 낮음 |
| Image.png | `.png` | O | 중 | OCR로 본문 텍스트는 추출되지만 줄바꿈, 문맥, 정확도는 원본 대비 추가 검토가 필요함 |

- 파싱 품질 기준: 원본 대비 텍스트 추출 정확도
- 판단 근거: Docker 실행 로그에서 출력한 `text[:200]` 기준

## 2. 검색 품질 테스트

현재 구성은 `MockLLM`을 사용하고 있어 QueryEngine의 최종 응답이 실제 자연어 답변이 아니라 더미 출력(`text text text ...`)으로 반환됩니다. 아래 평가는 현재 상태 기준 초안이며, 실제 검색 성능 평가는 실제 LLM 연결 이후 다시 수행해야 합니다.

| 파일 | 질문 | 기대 답변 (원본 기준) | 실제 응답 | 검색 품질 (상/중/하) | 판단 근거 |
|------|------|-------------------|----------|:------------------:|----------|
| Text.txt | 한계기업의 정의는 무엇인가? | 최근 3개 회계연도 말 이자보상비율이 연속 1 미만인 기업이라는 정의 조항 | `text text ...` | 하 | MockLLM 사용으로 실제 의미 있는 답변 생성 불가 |
| Policy.pdf | 연구비 관리 지침의 목적은 무엇인가? | 연구과제 관리 및 연구비 집행 세부사항을 정하는 것 | `text text ...` | 하 | 문서 파싱은 양호하지만 최종 응답 생성기가 더미 모델임 |
| SRS.docx | 시스템 요구사항 중 가장 중요한 기능 요구는 무엇인가? | 문서 원문 기준 기능 요구사항 요약 | `text text ...` | 하 | docx는 로드되지만 응답 생성 결과 검증 불가 |
| CRA.xlsx | 고객 요구사항 분석표에서 확인하는 주요 항목은 무엇인가? | 기술적 타당성, 구현 가능성, 테스트 가능성 등 | `text text ...` | 하 | 표 구조가 평탄화되어 검색 난이도가 높고 MockLLM이라 응답도 부정확 |
| DESIGN.hwp | 공고문에서 신규지원 대상 과제의 모집 취지는 무엇인가? | 디자인산업기술개발사업 신규 지원대상 연구개발과제 공고 내용 | `text text ...` | 하 | HWP 파싱 깨짐이 있어 검색 전 단계부터 품질 저하 |
| Image.png | 이미지 문서가 설명하는 주제는 무엇인가? | Exhibit B와 mermaids migration 관련 설명 | `text text ...` | 하 | OCR 추출은 되었으나 최종 응답은 더미 출력 |

- 검색 품질 기준: 기대 답변 대비 실제 응답 정확도
- 판단 근거: 현재 `MockLLM(max_tokens=256)` 사용 중이라 응답 생성이 과제용 더미 상태임

## 3. 미지원 포맷 해결 방안

| 확장자 | 실패 원인 | 시도한 해결 방법 | 해결 후 파싱 품질 | 해결 후 검색 품질 |
|--------|----------|----------------|:------------------:|:------------------:|
| `.docx` | `docx2txt` 미설치 | `requirements.txt`에 `docx2txt` 추가 후 Docker 재빌드 | 중 | 하 |
| `.xlsx` | `openpyxl` 미설치 | `requirements.txt`에 `openpyxl` 추가 후 Docker 재빌드 | 중 | 하 |
| `.hwp` | `olefile` 미설치 | `requirements.txt`에 `olefile` 추가 후 Docker 재빌드 | 하 | 하 |
| `.png` | OCR 라이브러리 및 Tesseract 부재 | `pytesseract` 추가, `Dockerfile`에 `tesseract-ocr`, `tesseract-ocr-kor` 설치 | 중 | 하 |

| 개선 방법 | 적용 대상 | 테스트 질문 | 개선 전 응답 | 개선 후 응답 | 효과 (상/중/하) |

| 표 문서 전처리 후 인덱싱 | `CRA.xlsx` | 고객 요구사항 분석 항목은 무엇인가? | 컬럼이 평탄화된 상태 | 행과 열 의미가 보존된 텍스트 기대 | 중 |
